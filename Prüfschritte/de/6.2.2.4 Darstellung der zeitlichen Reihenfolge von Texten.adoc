== Was wird geprüft?

Bei der Echtzeit-Texteingabe sollen die Eingaben aus jeder Quelle einschließlich der lokalen Quelle in der zeitlichen Reihenfolge ihres Abschlusses geordnet erscheinen. Der Abschluss einer Eingabe bestimmt die zeitliche Anordnung verschiedener Textblöcke. Als Abschluss gilt die Eingabe eines Punktes mit nachfolgendem Leerzeichen, ein Zeilenumbruch, oder eine mehr als fünfsekündige Pause. Wird ein Textblock im Nachgang editiert wird dessen Abschlusszeit auf das zuletzt eingegebene Zeichen gesetzt.

== Warum wird das geprüft?

Die Reihenfolge von Texteingaben verschiedener Teilnehmer soll in der Darstellung insgesamt den zeitlichen Ablauf der Kommunikation widerspiegeln. Gleichzeitig sollen die Textblöcke bei gleichzeitigen Eingaben aus mehreren Quellen nicht allzu fein in einzelen Bestandteile aufgeteilt werden, da sonst die Lesbarkeit leidet.

== Wie wird geprüft?

=== 1. Anwendbarkeit des Prüfschritts

Der Prüfschritt ist anwendbar, wenn das Webangebot Zwei-Wege-Kommunikation mit Echtzeit-Texteingabe (RTT, Real-Time Text) unterstützt.

=== 2. Prüfung

. Die Zwei-Wege-Sprachkommunikation mit Unterstützung von Echtzeit-Texteingabe wird gestartet.
. Mehrere Teilnehmer geben über 30 Sekunden hinweg fortlaufend Text ein.
. Prüfen, ob der Text in lesbaren Textblöcken erscheint, so aufgeteilt, das eine zeitliche Abfolge ablesbar ist.
. Mehrere Teilnehmer geben erneut kontiuierlich zeitgleich Text ein, wobei Teilnehmer 1 die Eingabe früher abschließt als Teilnehmer 2.
. Prüfen, ob der aus der Eingabe von Teilnehmer 1 entstandene Textblock früher angeordnet ist als der von Teilnehmer 2.

=== 3. Hinweise 

* Kontinuierliche Texteingaben sollen als ein durchgehender Block dargestellt werden, es sein denn eine andere Quelle sendet zur selben Zeit, in welchem Fall die Eingaben im Wechsel dargestellt werden. Die Reihenfolge bei mehreren gleichzeitigen Texteingaben in einspaltiger Ansicht ist dabei nur annähernd, damit Textblöcke für die bessere Lesbarkeit zusammengehalten werden.
* Der Prüfschritt macht keine Vorgaben, ob die durch Eingaben erzeugten Textblöcke zuoberst oder am Ende eingefügt werden. Es zählt die jeweilige Reihenfolge.

=== 4. Bewertung 
==== Erfüllt

* Texeingaben werden als lesbare Blöcke dargestellt (also bei gleichzeitigen Eingaben nicht zu fein im Wechsel aufgeteilt)
* Die Reihenfolge der Textblöcke entspricht dem zeitlichen Ablauf der Komunikation

==== 6.2.2.4 Darstellung der zeitlichen Reihenfolge von Texten
____
[.BLOCK_LANG_EN]
--
Where ICT provides real-time bidirectional voice communication, and includes RTT presentation capabilities,
the ICT shall present the text from each source, including the local source, as blocks of text that are arranged in order
based on the point in time that each block of text is terminated by any sentence-terminating punctuation character
followed by a space, or a line separator character is entered or received, or 5 seconds passes without a new character
being entered or received. Editing of text in a block causes the entire block's termination time to change to the time of
the last edited character.

NOTE 1:
Text blocks from the same source are presented contiguously, forming a single block, unless an
intervening text block from a different source is received. For example, the phrases 'J.D. Clampett is here!
But no one else is.' will appear as one continuous text presentation when no other sources are sending
concurrently. If, however, another source sends text at the same time, then within a single column view,
the blocks are presented in chronological order, with text blocks from different sources interleaved but
kept distinct.

NOTE 2:
This requirement aims to establish an approximate chronological order for displaying text from different
sources, while maintaining text blocks together for readability. Precise timing between texts from
different sources received concurrently is unnecessary and would reduce readability in most layouts.

NOTE 3:
Presentation aspects of RTT are presented in ETSI TR 103 708 [i.59] clause 7.2.

NOTE 4:
The events terminating a block of text in the present clause is the minimum set. For smooth presentation
other events can be added to a product, such as end of phrase or reasons found by linguistic analysis in
languages not using explicit delimiter characters.

NOTE 5:
See clause 6.2.5 of the present document for additional information regarding adding and erasing of text.
--
